SNOMED CT hybrid search · architecture

Three models, three architectures

The pipeline runs three neural networks of three distinct classes — not three LLMs. A decoder autoregressively generates text; a bi-encoder projects text into a shared vector space; a cross-encoder scores a query–passage pair with joint attention. Exactly one is domain-adapted to biomedicine.

The bi-encoder/cross-encoder split is retrieve-then-rerank: ② encodes independently → precomputable, sublinear ANN recall over 1,024,825 vectors; ③ scores pairs jointly → higher precision but quadratic attention, so it only touches the k=15 already recalled. Serving topology

Out-of-process · HTTP

gemma → Ollama

Separate daemon (llama.cpp/Metal backend) exposing an OpenAI-compatible API on :11434. It owns weight loading, quantization and OLLAMA_KEEP_ALIVE; the app issues an HTTP chat/completions call. Any compatible endpoint is a drop-in — the LLM is swappable and optional.

① gemma3:12b
In-process · MPS

BioLORD & reranker → PyTorch

Loaded inside the FastAPI/uvicorn worker via sentence-transformers on MPS — no daemon, no serialization, direct tensor calls. Weights are lazy-loaded once and cached; embeddings land in pgvector, the reranker runs on the fused candidate set.

05

What Postgres does

One Postgres instance is the entire retrieval engine — lexical search, vector search and hierarchy filtering, all fused in a single query. No Elasticsearch, no separate vector database: one transactional store, three extensions doing three jobs.

Lexical channel tsvector + GIN to_tsquery('w1:* & w2:*')

Full-text over a custom unaccent_simple config (unaccent, no stemming). Multi-prefix, order-independent, accent-insensitive matching, ranked by length-normalized ts_rank(…,1).

Semantic channel pgvector · HNSW embedding <=> $qvec

BioLORD's 768-d vectors live in a vector column, searched by cosine through an HNSW index; iterative index scans keep filtered ANN accurate when a subtree filter is applied.

Hierarchy filter transitive closure + GIN ancestors @> ARRAY[X]

A precomputed concept_ancestors(ancestors bigint[]) turns “is C under X?” into a single indexed lookup — descendants-or-self with no per-query graph traversal.

All three run inside one SQL plan, and RRF fusion is computed in SQL too: the two rankings are merged, deduped by concept and joined to the FSN before a single result set ever leaves the database.

07

Building on prior art

The closest prior work — Chang, Mai et al. (CSIRO) — established that semantic Triplet-BERT retrieval over SNOMED beats lexical baselines on low-lexical-overlap queries, trained from the ontology's own synonyms. We keep that thesis — it is our semantic channel — but extend a single-stage, English, semantic-only retriever into a full system:

Hybrid, not semantic-only

Lexical + semantic fused with RRF (plus an exact_first pin): the recall of embeddings and the precision of exact term matches, not a trade-off between them.

No model training

Off-the-shelf BioLORD-2023-M — already pretrained on UMLS/SNOMED and multilingual — instead of fine-tuning a bespoke Triplet-BERT. Zero training cost.

Dirty, any-language input

An LLM pre-process step (gemma) translates, expands acronyms and fixes typos, so real "fast note" input in any language works — the paper is English-focused.

Retrieve-then-rerank

A second stage: the cross-encoder reranks the top-15 (blended with RRF). The prior work is single-stage retrieval.

Hierarchy filter

A precomputed transitive closure (concept_ancestors + GIN) restricts results to the descendants-or-self of any concept — a practical clinical constraint.

Reproducible local stack

One Postgres + pgvector store for both channels, HNSW-indexed, runs on a laptop and points at any SNOMED release with a path change — an experiment becomes a deployable system.
